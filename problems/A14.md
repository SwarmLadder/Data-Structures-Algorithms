# A14 — Count safe placements of n schedulers

**Hard** · Backtracking / constraints

## The challenge

**Constraints:** 0 <= n <= 9.

### A. From baseline to the right data structure

Placing n queens by trying every n×n board blindly is enormous. Backtracking places one queen per row and prunes columns and diagonals already attacked.

### B. Invariant or recurrence and why it works

At depth row, the chosen columns and two diagonal sets encode exactly the previous rows’ placements. A candidate column is legal iff no column, row−col diagonal, or row+col diagonal is occupied; after recursion restore all three sets.

### C. Work through a real example

- Function arguments: `[4]`
- Expected output: `2`

For n=4 there are exactly two valid arrangements. For n=2 and n=3 there are none. For n=1 there is exactly one.

### D. Executable reference implementation

```python
"""Reference answer for A14. See the problem statement before reading.
"""
def solve(n):
    count = 0
    cols, diag_up, diag_down = set(),set(),set()
    def backtrack(row):
        nonlocal count
        if row == n:
            count += 1; return
        for col in range(n):
            d1,d2 = row-col,row+col
            if col in cols or d1 in diag_up or d2 in diag_down:
                continue
            cols.add(col); diag_up.add(d1); diag_down.add(d2)
            backtrack(row+1)
            cols.remove(col); diag_up.remove(d1); diag_down.remove(d2)
    backtrack(0)
    return count
```

### E. Complexity derivation

Worst-case search is exponential/factorial-scale (bounded by O(n!) candidate partial placements under distinct columns); O(n) search state and recursion depth, excluding any materialized solutions.

### F. Failure modes that expose memorized solutions

A forgotten set removal contaminates sibling choices and silently drops solutions. Counting arrangements is cheaper in output memory than returning every board.

### G. Transfer the technique
