# I03 — Count consecutive batches matching a net total

**Medium** · Prefix sum frequency

## The challenge

**Constraints:** 0 <= len(nums) <= 100000; signed integer values.

### A. From baseline to the right data structure

Two nested loops can check all contiguous sums but cost O(n²). Prefix-sum algebra converts each range into the difference of two prefix totals.

### B. Invariant or recurrence and why it works

Before reading the next value, freq counts earlier prefixes including empty prefix 0 once. New current prefix P forms a target-sum range with every earlier prefix P−target. Count matches **before** adding P to prevent empty-range matches.

### C. Work through a real example

- Function arguments: `[[1, 1, 1], 2]`
- Expected output: `2`

For [1,-1,0] and target 0: prefix 1 gives zero new ranges; prefix 0 matches the initial zero once; next prefix 0 matches two prior zeros, yielding 3 total.

### D. Executable reference implementation

```python
"""Reference answer for I03. See the problem statement before reading.
"""
def solve(nums, target):
    from collections import defaultdict
    freq = defaultdict(int)
    freq[0] = 1
    prefix = answer = 0
    for x in nums:
        prefix += x
        answer += freq[prefix - target]
        freq[prefix] += 1
    return answer
```

### E. Complexity derivation

O(n) expected hash time and O(n) distinct prefix sums in worst case. Counts may reach Θ(n²), so fixed-width languages need wide integer types.

### F. Failure modes that expose memorized solutions

A sliding window that shrinks when sum exceeds target is invalid with arbitrary negatives. Forgetting freq[0]=1 misses ranges starting at index 0.

### G. Transfer the technique

Variant: count ranges with sum divisible by k by storing normalized prefix remainders, paying attention to negative remainder semantics.
