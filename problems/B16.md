# B16 — Product of metrics excluding current

**Medium** · Prefix and suffix

## The challenge

Return result[i] equal to the product of all nums[j] for j != i. Do not use division. Arrays may contain one or more zeros.

**Constraints:** 2 <= len(nums) <= 100000; reference outputs fit signed 64-bit integers.

**Function to implement:** `def solve(nums):`

## Examples

2. Input arguments: `[[-1,1,0,-3,3]]` → expected output: `[0,0,9,0,0]`

### A. From baseline to the right data structure

Division by the total product fails when zeros occur and may be disallowed by the contract. Instead multiply values to the left and right of each index.

### B. Invariant or recurrence and why it works

First pass: before index i, `left` is the product of nums[:i], so store it in result[i]. Second pass from right: `right` is the product of nums[i+1:], and multiply it into result[i].

### C. Work through a real example

- Function arguments: `[[1, 2, 3, 4]]`
- Expected output: `[24, 12, 8, 6]`

For [1,2,3,4], left products are [1,1,2,6]; successive right multipliers make final [24,12,8,6]. For [0,2,3], output [6,0,0] naturally without special zero cases.

### D. Executable reference implementation

```python
"""Reference answer for B16. See the problem statement before reading.
"""
def solve(nums):
    result = [1] * len(nums)
    left = 1
    for i, x in enumerate(nums):
        result[i] = left
        left *= x
    right = 1
    for i in range(len(nums) - 1, -1, -1):
        result[i] *= right
        right *= nums[i]
    return result
```

### E. Complexity derivation

O(n) time and O(n) output space. With output excluded, extra multipliers use O(1) space; large-integer products have arithmetic costs.

### F. Failure modes that expose memorized solutions

Do not use division or recompute a product for every index. Empty product is 1; the two passes handle zero and repeated zeros correctly.
