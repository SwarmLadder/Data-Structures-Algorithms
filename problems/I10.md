# I10 — Locate a target in rotated configuration IDs

**Medium** · Binary search / rotation

## The challenge

**Constraints:** 0 <= len(nums) <= 100000; no duplicate values.

### A. From baseline to the right data structure

Ordinary binary search needs globally sorted input. A rotation of a strictly increasing array guarantees that at least one of the two halves around mid is sorted.

### B. Invariant or recurrence and why it works

If nums[lo]≤nums[mid], the left half is sorted; compare target against that half’s range to decide whether to retain it. Otherwise the right half is sorted and its bounds decide. Each step discards half the candidates.

### C. Work through a real example

- Function arguments: `[[4, 5, 6, 7, 0, 1, 2], 0]`
- Expected output: `4`

For [4,5,6,7,0,1,2] searching 0, initial mid is 7; left half [4,5,6,7] is sorted but excludes 0, so move lo right; further bisection finds index 4.

### D. Executable reference implementation

```python
"""Reference answer for I10. See the problem statement before reading.
"""
def solve(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[lo] <= nums[mid]:
            if nums[lo] <= target < nums[mid]: hi = mid - 1
            else: lo = mid + 1
        else:
            if nums[mid] < target <= nums[hi]: lo = mid + 1
            else: hi = mid - 1
    return -1
```

### E. Complexity derivation

O(log n) time and O(1) space under the stated distinct-value rotation assumption.

### F. Failure modes that expose memorized solutions

With duplicates, `nums[lo] == nums[mid]` can obscure which half is sorted, and worst-case search may degrade to O(n). Do not apply the same proof without checking uniqueness.
