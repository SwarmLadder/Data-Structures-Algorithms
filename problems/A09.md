# A09 — Longest strictly increasing deployment run (not necessarily contiguous)

**Medium** · Patience sorting / binary search

## The challenge

Return the length of the longest strictly increasing subsequence, which may skip elements. Equal values do not extend the subsequence.

**Constraints:** 0 <= len(nums) <= 100000.

**Function to implement:** `def solve(nums):`

### A. From baseline to the right data structure

The O(n²) baseline compares each element to all earlier smaller values. Maintain, for each subsequence length, the smallest possible ending value using binary search.

### B. Invariant or recurrence and why it works

tails[i] is the minimum achievable final value for a strictly increasing subsequence of length i+1 among elements processed. A smaller tail dominates a larger one for the same length because every extension remains possible.

### C. Work through a real example

- Function arguments: `[[10, 9, 2, 5, 3, 7, 101, 18]]`
- Expected output: `4`

For [10,9,2,5,3,7,101,18], tails evolves toward [2,3,7,18] and its length 4 is the LIS length. The tails array itself need not be a subsequence.

### D. Executable reference implementation

```python
"""Reference answer for A09. See the problem statement before reading.
"""
def solve(nums):
    from bisect import bisect_left
    tails = []
    for x in nums:
        pos = bisect_left(tails, x)
        if pos == len(tails): tails.append(x)
        else: tails[pos] = x
    return len(tails)
```

### E. Complexity derivation

Each of n numbers uses bisect_left on at most n tails, O(n log n) time and O(n) space.

### F. Failure modes that expose memorized solutions

Use bisect_left for **strict** increasing sequences so equal values replace rather than extend; bisect_right solves a different nondecreasing variant.
