# B13 — Common items across sorted inventories

**Easy** · Two pointers

## The challenge

**Constraints:** 0 <= len(a), len(b) <= 100000.

### A. From baseline to the right data structure

Sorting a concatenated set discards multiplicity, which may be required by inventory counts. Since both lists are sorted, scan with two pointers.

### B. Invariant or recurrence and why it works

At indexes i,j, if values match, append one copy and advance both. If a[i]<b[j], then a[i] cannot match any later b value; advance i. The symmetric argument applies when b[j]<a[i].

### C. Work through a real example

- Function arguments: `[[1, 2, 2, 3], [2, 2, 4]]`
- Expected output: `[2, 2]`

For a=[1,2,2,3] and b=[2,2,4], both 2 values match one-to-one, yielding [2,2]. Advance both pointers after each match to avoid using one item twice.

### D. Executable reference implementation

```python
"""Reference answer for B13. See the problem statement before reading.
"""
def solve(a, b):
    i = j = 0
    result = []
    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            result.append(a[i]); i += 1; j += 1
        elif a[i] < b[j]:
            i += 1
        else:
            j += 1
    return result
```

### E. Complexity derivation

O(n+m) time, O(t) output for t matches, O(1) extra pointer memory beyond output.

### F. Failure modes that expose memorized solutions

Using set intersection returns only unique values. Incrementing only one pointer after a match can repeat the same occurrence. Empty inputs yield empty output.

### G. Transfer the technique

Variant: return only distinct shared values, modifying the skip-duplicate logic; compare contracts and outputs.
