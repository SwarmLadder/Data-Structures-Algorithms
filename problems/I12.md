# I12 — Implement an LRU response cache

**Medium** · Ordered map

## The challenge

Process operations ["put", key, value] and ["get", key] on a cache of capacity slots. Return the list of results from get operations only (value or -1 when missing). Both a successful get and a put of an existing key make that key most recently used. Capacity may be zero.

**Constraints:** 0 <= capacity <= 10000; 0 <= operations <= 100000; integer keys/values.

**Function to implement:** `def solve(capacity, operations):`

## Examples

1. Input arguments: `[2,[["put",1,1],["put",2,2],["get",1],["put",3,3],["get",2],["put",4,4],["get",1],["get",3],["get",4]]]` → expected output: `[1,-1,-1,3,4]`
2. Input arguments: `[0,[["put",1,1],["get",1]]]` → expected output: `[-1]`

### A. From baseline to the right data structure

A plain dictionary offers fast key lookup but not automatic least-recently-used eviction. `OrderedDict` lets us move a touched key to newest position and remove the oldest key.

### B. Invariant or recurrence and why it works

The dictionary’s iteration order represents increasing recency, from least recent to most recent. Every successful get and put(existing) moves that key to the end. If capacity is exceeded, pop from the front.

### C. Work through a real example

- Function arguments: `[2, [["put", 1, 1], ["put", 2, 2], ["get", 1], ["put", 3, 3], ["get", 2], ["put", 4, 4], ["get", 1], ["get", 3], ["get", 4]]]`
- Expected output: `[1, -1, -1, 3, 4]`

Capacity 2 with put(a,1), put(b,2), get(a), put(c,3): touching a makes b oldest, so c insertion evicts b. A later get(b) returns -1.

### D. Executable reference implementation

```python
"""Reference answer for I12. See the problem statement before reading.
"""
def solve(capacity, operations):
    from collections import OrderedDict
    cache = OrderedDict()
    result = []
    for op in operations:
        if op[0] == 'get':
            key = op[1]
            if key not in cache:
                result.append(-1)
            else:
                result.append(cache[key])
                cache.move_to_end(key)
        else:
            key, value = op[1:]
            if key in cache:
                cache.move_to_end(key)
            cache[key] = value
            if len(cache) > capacity:
                cache.popitem(last=False)
    return result
```

### E. Complexity derivation

Expected O(1) per get/put with a hash-backed ordered map; O(capacity) stored entries plus output list for get results.

### F. Failure modes that expose memorized solutions

Updating an existing key also counts as use. When capacity=0, every put is immediately evicted. FIFO insertion order is not the LRU policy.

### G. Transfer the technique

Variant: implement the data structure without OrderedDict using a hash table plus doubly linked list; prove each operation uses constant pointer updates.
