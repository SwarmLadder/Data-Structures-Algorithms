# I11 — Find the smallest value in a rotated array

**Medium** · Binary search / boundary

## The challenge

A strictly increasing list was rotated some number of positions. Return its smallest value in logarithmic time. The input is nonempty and has no duplicates.

**Constraints:** 1 <= len(nums) <= 100000.

**Function to implement:** `def solve(nums):`

## Examples

1. Input arguments: `[[3,4,5,1,2]]` → expected output: `1`
2. Input arguments: `[[4,5,6,7,0,1,2]]` → expected output: `0`

### A. From baseline to the right data structure

A linear scan finds the minimum but costs O(n). In a rotated strictly increasing array, comparing nums[mid] with nums[hi] identifies the side containing the rotation minimum.

### B. Invariant or recurrence and why it works

If nums[mid]>nums[hi], the minimum lies strictly to the right of mid; otherwise it lies at mid or to the left. Keep a closed candidate range [lo,hi] and reduce its width each step.

### C. Work through a real example

- Function arguments: `[[3, 4, 5, 1, 2]]`
- Expected output: `1`

For [4,5,6,1,2,3], mid index 2 holds 6>3, so lo=3; the remaining range begins at 1, which is the minimum.

### D. Executable reference implementation

```python
"""Reference answer for I11. See the problem statement before reading.
"""
def solve(nums):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] > nums[hi]:
            lo = mid + 1
        else:
            hi = mid
    return nums[lo]
```

### E. Complexity derivation

O(log n) time, O(1) space, for a nonempty rotated array with distinct values.

### F. Failure modes that expose memorized solutions

If duplicates are permitted, a comparison equal to nums[hi] may be ambiguous and require hi−−, causing worst-case O(n). Empty input needs a defined error policy.

### G. Transfer the technique

Variant: find both minimum value and rotation index, then use it to search for any target.
