# B10 — Recover a missing sequence ID

**Easy** · Arithmetic invariants

## The challenge

An array holds n distinct numbers from 0 through n, missing exactly one. Return the missing number; an empty array means zero is missing.

**Constraints:** 0 <= n <= 100000.

**Function to implement:** `def solve(nums):`

## Examples

1. Input arguments: `[[3,0,1]]` → expected output: `2`
2. Input arguments: `[[0,1]]` → expected output: `2`

### A. From baseline to the right data structure

Brute force checks which number from 0..n is absent, possibly using a set. Arithmetic exploits the invariant that exactly one value is missing and all others appear once.

### B. Invariant or recurrence and why it works

The complete expected sum is n(n+1)/2. Subtract the observed sum; all present values cancel, leaving precisely the missing number. This proof depends on no duplicates or out-of-range values.

### C. Work through a real example

- Function arguments: `[[3, 0, 1]]`
- Expected output: `2`

For [3,0,1], n=3; expected sum=6, observed=4, missing=2. For [], n=0, the required 0..0 set has the single missing value 0.

### D. Executable reference implementation

```python
"""Reference answer for B10. See the problem statement before reading.
"""
def solve(nums):
    n = len(nums)
    return n * (n + 1) // 2 - sum(nums)
```

Run `python -m tools.practice check B10 problems/reference/B10.py` to verify it against all six published fixtures. Work through the variable changes on one example **without** executing the code before comparing your trace.

### E. Complexity derivation

O(n) time to sum the array, O(1) extra space. In fixed-width languages the formula can overflow; Python integers avoid fixed-width overflow but not arbitrary-size arithmetic costs.

### F. Failure modes that expose memorized solutions

Do not apply this to data with duplicates: [0,0] violates the assumptions and gives a misleading difference. Avoid integer division mistakes in other languages.
